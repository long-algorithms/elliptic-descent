# v0.2 acceptance and reproducibility

This release satisfies the **arithmetic/local foundation** gate. It is not the
v0.3 complete-relative-descent gate. No release criterion has been weakened to
turn a partial candidate search into a complete descent.

| Requirement | Implementation and verification |
|---|---|
| Finite-support square classes | Sage `K(S,2)`, all primes above S, coordinate round trips, class-group-2-torsion fixture |
| Norm constraints | Exact affine F2 elimination; exhaustive small-system comparisons; independent norms and witnesses |
| Local filtering with unknown | Modular obstructions, strong Hensel, real certificates; explicit node/depth limits |
| Arithmetic assumptions | Explicit `proof=True/False`, GRH propagation, supplied bases unverified by default |
| Sage/PARI integration | Actual backend tests, not mocks; imported map identities checked in SymPy |
| Restricted completeness statements | Exact specified norm fibre; local certificate correctness; documented good-reduction bound |
| Benchmarks | Separate arithmetic/local/verification costs; proof, scope, budgets, metadata, JSONL artifacts |

## Reproduce the checks

```sh
python -m pip install -e '.[test]'
python -m pytest -q
python benchmarks/geometry.py --repeats 3 --verify
python benchmarks/foundation.py --repeats 3 --verify

sage -pip install -e '.[test]'
ELLIPTIC_DESCENT_REQUIRE_SAGE=1 sage -python -m pytest -q
sage -python benchmarks/foundation.py --sage --repeats 1 --verify
```

The Python suite and the Sage suite share the same exact reference code.
The Sage job additionally tests the real class-group/S-unit and PARI calls.
Its Docker image is pinned by digest in the workflow. Test counts and final
verification outcomes are recorded on the release PR, rather than claiming
that tests pass solely because they exist.

## Benchmark interpretation

Both runners produce machine-readable JSONL. Foundation records distinguish
construction of `K(S,2)` from the candidate-screening stage, and local-search
time from certificate-verification time. They include support, basis dimension,
candidate count, truncation, unresolved cases, backend/proof assumptions,
search budgets, Python/SymPy/platform details, revision, and process peak RSS.

These are in-process repetitions, not cold-cache timings. RSS is the cumulative
process peak with native units explicitly stated, not per-stage Python heap
usage. The initial benchmark corpus is for reproducibility and regression;
it is not evidence of superiority to Magma, eclib, or PARI. Thread counts are
fixed in the Sage CI job. Arithmetic and local decisions are more important
than small timing fluctuations on shared CI machines.

A manual run can supply `GITHUB_SHA` when the working directory is not a Git
checkout. CI normally obtains the revision from Git; its PR merge ref may
differ from the feature branch's head. Retain the corresponding workflow URL.

## Explicitly unfinished work

- Complete relative Selmer parametrization, orientations, rational-scalar and
  covering-equivalence quotients, and global proof of exhaustiveness.
- Etale-product arithmetic for reducible quartics (the geometric kernel already
  supports squarefree products).
- Complete real-solubility decision procedure and optimized p-adic algorithms.
- Full curve-level 4-Selmer group, pairing integration, torsion bookkeeping,
  minimization/reduction and practical rational-point search.

The first item is the main v0.3 obligation. `FoundationResult` therefore
reports `relative_descent_complete=False` unconditionally. Unknown local
candidates remain retained and truncated norm fibres retain their full count.
