# v0.4.0 — relative 4-descent over the rationals

This release covers **every squarefree polynomial of degree four over Q**,
with the canonical quartic-to-Jacobian marking. It combines the irreducible,
two-quadratic and rational-root implementations and their exact equivalence
rules. It does not compute the full curve-level 4-Selmer group.

## Mathematical contract

For `C: Y^2=F(X,Z)`, return all everywhere locally soluble relative 2-coverings
`D -> C` up to isomorphisms over the identity of the specified C. The models
are intersections of quadrics, with explicit degree-four maps to C and
canonical degree-sixteen compositions to its Jacobian. The source can itself
be locally insoluble; an empty result is a Sha statement only with the
additional appropriate source-local-solubility information.

| Factorization | Arithmetic | Orientations per accepted scalar-square class |
|---|---|---:|
| `4` | quartic number field | 2 |
| `2+2` | product of quadratic fields | 2 |
| `3+1` | cubic field and Q | 1 |
| `2+1+1` | quadratic field and Q squared | 1 |
| `1+1+1+1` | Q to the fourth power | 1 |

For a rational root, the orientation identification is an explicit CRT unit
with square 1 and norm -1, with a verified coordinate transformation. The
other two types retain distinct orientations. No additional target
translations, factor permutations, or rational-torsion quotients are applied.

The mathematical arguments are in [relative descent](relative-descent.md),
[two-quadratic descent](two-quadratic-descent.md) and
[rational-root descent](rational-root-descent.md). In particular, norm-fibre
exhaustion alone is not a Selmer computation: the support theorem, rational
scalar quotient, orientation accounting and all local decisions are required.

The API takes five ascending exact rational coefficients, with nonzero leading
coefficient and nonzero discriminant, or a `QuarticTwoCover` object. Cubic
presentations (including a branch point at infinity) and generalized equations
`Y^2+H(X,Z)Y=G(X,Z)` require explicit conversion and are not accepted directly.
Arbitrary externally marked maps to other elliptic-curve models are not
silently inferred from matching invariants.

## Completion, evidence and trust

Complete mode has no artificial candidate, local-depth or node cutoff. It
terminates in the declared smooth domain by finite arithmetic enumeration and
the local compactness/Hensel argument; this is not a feasible-runtime promise
for every input. Explicit limits can return partial results. A resource failure
or exception is never an insolubility certificate.

Every result now retains `candidate_space`, the exact affine F2 transversal
used in the computation. `accounting_consistent` checks independent basis
vectors, scalar/quotient dimensions, membership, range, and unique labels.
Completion requires that all its classes have been processed. A same-length
list with a duplicate replacing a missing class can no longer pass merely
because its length agrees with the claimed count.

This accounting audit verifies the *recorded* space. It does not independently
prove the class-group computation or reconstruct the true Selmer set. The
backend is responsible for the support, basis, and norm calculation. Likewise,
`verify_evidence()` checks the model and local evidence, not a second independent
class-group computation. Manually constructing or replacing result fields
cannot create a proof. The runtime, exact arithmetic libraries and the cited
mathematical algorithms remain trusted dependencies; this is not a formally
verified implementation or an external mathematical review.

`proof=True` requests Sage's certified number-field arithmetic. Nonrational
factors computed with `proof=False` retain their GRH assumption. A fully split
algebra uses rational arithmetic only and need not acquire a spurious GRH
dependency. `certified` requires complete accounting and decisions, unconditional
arithmetic, and valid orientation hypotheses. A returned empty list is an empty
descent conclusion only when those conditions hold.

## Release acceptance matrix

| Obligation | Repeatable checks |
|---|---|
| Exact algebra, norms, maps | multiplication matrices versus resultants; CRT round trips; generic geometric audits |
| Exhaustive arithmetic | certified Sage spaces, class-group-2-torsion fixtures, explicit support/norm checks |
| Nonredundant classes | exact scalar quotient, dependent scalar images, orientation witnesses; candidate-space accounting |
| Local decisions | independently checked Hensel/modular/real certificates; singular reduction; limited searches retain unknown |
| All five patterns | unified Sage suite and the 22-case end-to-end benchmark corpus |
| Independent count checks | 14 eclib comparisons: six two-quadratic and eight rational-root sources with verified rational points |
| Fully split cross-check | enumerate 64 rational candidates without Sage square classes or the affine quotient routines; compare accepted classes |
| Failure paths | duplicate, out-of-space and missing candidates; wrong counts; altered maps/certificates; proof/budget modes |
| Package distribution | build wheel and sdist, inspect exact contents and metadata, test installed wheel outside the checkout |

The fully split cross-check uses the same local decision routine, with its
independent certificate checker. It is an independent **candidate enumeration**,
not an independent complete descent implementation. eclib comparisons are
cardinality checks, not class-by-class model comparisons. Published Magma
examples are regression fixtures; Magma is not executed by the test suite.

The benchmark-report validator fails on missing/duplicate fixtures, stale
package versions, conditional or unresolved results, wrong covering counts,
missing marked-map/eclib checks, artificial limits, or malformed timings.
Its JSON summary is a check of recorded results, not a new mathematical proof.
Timing observations on shared CI machines are not stable performance thresholds.

## Install, test and reproduce

```sh
sage -pip install -e '.[test]'
ELLIPTIC_DESCENT_REQUIRE_SAGE=1 sage -python -m pytest -q

sage -python benchmarks/relative.py --verify > relative-results.jsonl
sage -python benchmarks/two_quadratic.py --verify > two-quadratic-results.jsonl
sage -python benchmarks/rational_root.py --verify > rational-root-results.jsonl
sage -python benchmarks/etale.py --sage --verify > etale-results.jsonl
sage -python benchmarks/release_audit.py > release-audit.json
```

Solver and evidence-verification times remain separate. Records include proof
assumptions, support, dimensions, candidate counts, local work, transformations,
package/dependency versions and process memory. Repetitions share a process;
these are not cold-cache comparisons. All tests require genuine Sage in its
CI job; Python-only jobs explicitly skip Sage modules.

The CI packaging job also executes:

```sh
python -m pip install build
python -m build
python tools/check_distribution.py --directory dist
```

The wheel contains the complete Python package. The sdist additionally contains
tests, mathematical documentation, benchmark runners and the distribution
checker. The checker compares these bytes to the source, validates version and
license metadata, and writes `SHA256SUMS` and `release-manifest.json`. An
installed-wheel smoke test and the Python suite run outside the source checkout.
The source distribution is also rebuilt to a wheel. CI artifacts are not a
PyPI publication or a GitHub release/tag; those are separate publishing actions.

## Scope exclusions and next milestone

Not included: the full 4-Selmer group and its operations, exact Mordell-Weil rank
or saturation, arbitrary input markings, number-field base curves, cubic-input
conversion, general minimization/reduction, and practical large-height searches.
The next mathematical milestone remains v0.5: curve-level Selmer assembly with
its doubling map, pairing and torsion bookkeeping. Performance optimization
must preserve the existing exact reference paths and proof/status distinctions.
