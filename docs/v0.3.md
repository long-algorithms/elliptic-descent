# v0.3 acceptance and regression corpus

The v0.3 target is complete **relative** 4-descent for a squarefree irreducible
quartic over Q, with its canonical Jacobian map. This does not include full
curve-level 4-Selmer-group assembly. See [the mathematical contract and proof
argument](relative-descent.md) for the exact equivalence and trust boundary.

## Release gates

| Gate | Implementation | Acceptance check |
|---|---|---|
| Exhaustive finite candidate set | Certified `K(S,2)`, support lemma, affine norm constraint | Class-group-2-torsion fixture, independent norms, coordinate round trips |
| Nonredundant quotient | Image of rational `-1` and support primes; exact F2 quotient | Exhaustive small-vector-space comparisons; quadratic-subfield dependencies |
| Oriented maps | Norm-pair equivalence; retain both signs | Exact scalar-square transformation identities and opposite-map tests |
| Real decision | Exact root isolation and sign patterns | Zero/two/four-real-root cases and altered certificates |
| Finite decisions | All residue solutions, strong Hensel, no default cutoff | Independent small-field enumeration; singular reduction at 2 and odd primes |
| Local model changes | Exact rational coordinate/equation matrices | Matrix-identity verification and corrupted-transformation tests |
| Empty descents | Exhaustive enumeration plus a checked obstruction for each class | All three published 571a1 quartics |
| Positive descent | Everywhere locally soluble models and explicit maps | Published positive quartic; known-point and rational-torsion examples |
| Certification | Explicit unconditional backend setting; retained conditional assumptions | Both proof modes, no skipped Sage tests in Sage CI |
| Reproducibility | JSONL end-to-end benchmarks and arithmetic exports | Dedicated CI artifacts and documented commands |

## Exact fixtures and conventions

Coefficients below are in ascending order. Counts of models are taken modulo
the target involution `Y -> -Y`; the fixed-target oriented output has twice
as many entries for an irreducible quartic.

| Fixture | Quartic coefficients | Locally soluble unoriented models |
|---|---|---:|
| Small positive | `(1,-1,0,0,1)` | 2 |
| Published positive | `(172,-120,20,12,-7)` | 1 |
| 571a1, first | `(-64,164,-52,-68,-11)` | 0 |
| 571a1, second | `(-7,-68,-142,112,-19)` | 0 |
| 571a1, third | `(-3,52,-232,60,-4)` | 0 |
| Rational 2-torsion Jacobian | `(1,0,0,0,1)` | 2 |

The positive and 571a1 reference counts come from the
[Magma handbook](https://magma.maths.usyd.edu.au/magma/handbook/text/1570).
They are **published fixtures**, not results of executing Magma in CI. The
small positive and `x^4+1` counts are regression results of this implementation;
they are not being advertised as independent Magma comparisons.

For `x^4+1`, both -1 and 2 are squares in the quartic field. The rational-scalar
image has dimension zero, not the size of the generating list. This fixture
protects against incorrectly subtracting `|S|+1` in the quotient dimension.
The two orientations remain distinct even in this case.

The third 571a1 norm fibre is already empty. The other two require rejecting
actual candidates. The suite checks the negative certificates independently,
not just the final list length. It also includes rational-square rescaling of
a quartic, nonmonic inputs, partial enumeration, local-budget exhaustion,
large-prime certification, singular inputs, and deliberately invalid evidence.

## Reproduce

```sh
sage -pip install -e '.[test]'
ELLIPTIC_DESCENT_REQUIRE_SAGE=1 sage -python -m pytest -q
sage -python benchmarks/relative.py --fixture all --verify --repeats 1
sage -python benchmarks/export_relative_arithmetic.py --output arithmetic-fixtures
```

The export contains exact field generators, scalar coordinates and norm-fibre
metadata, allowing local algorithms to be replayed without recomputing class
groups. An exported JSON file by itself is not an independent class-group
certificate. The arithmetic-export workflow and the end-to-end test workflow
both run a real, pinned Sage installation; neither mocks these calculations.
Final test counts, commit IDs and workflow results are recorded on PR #3.

## Benchmarks and optimization audit

`benchmarks/relative.py` records one JSON object per fixture and repetition.
Solver time excludes the separate evidence-verification time. Arithmetic and
construction/local costs, coefficient bit lengths, local work units, model
changes, scope, proof status, limits, and environment are included. Peak RSS
is cumulative process memory in explicitly described native units. Repeated
runs share a process and may benefit from caches.

The first v0.3 attempt exposed expensive singular reductions at 7, 19, 229
and 271. The fix is a verified change of integral model, not a higher arbitrary
search cap or a weaker correctness criterion. Every transformation is invertible
over Q and its exact matrices are checked before transferring a local verdict.
The bounded search still returns unknown when its work or depth limit is reached.

`max_nodes` counts algebraic residue-search work units; it is not a bound on
class-group work, factorization, model-improvement arithmetic, or elapsed time.
`max_depth` bounds the digit search on the improved model, not the original
unimproved coordinates. The preprocessing itself terminates by a discriminant
valuation argument and a fixed bound on neutral steps; stopping preprocessing
does not stop or truncate the subsequent complete local search.

Negative certificate verification intentionally uses a different residue
algorithm. For difficult primes its own budget may need increasing; returning
false means evidence was not verified, not that an insoluble model became
soluble. `full_geometry=True` additionally invokes the retained, slower generic
Groebner audits when calling `result.verify_evidence(...)`.

## Deliberate exclusions

This release does not support reducible quartics in the complete arithmetic
interface, arbitrary externally marked maps to elliptic curves, full Selmer
group operations, exact ranks, saturation, complete minimization/reduction,
or practical large-height point search. The supporting geometry and PARI
import APIs remain available. The elementary integral changes used by local
solubility do not constitute the full Cremona–Fisher–Stoll minimization method.

No speed superiority to Magma, PARI, or eclib is asserted. Completeness describes
the supported mathematical domain and absence of artificial cutoffs, not a
promise of feasible runtime on every input.
